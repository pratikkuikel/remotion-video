# Guided creative workflow

Use this when the user chooses Guided mode. Each stage ends with a concrete artifact the user can react to. Ask in small related groups; carry forward answers already given. The user may say “decide for me” at any stage: make that decision and continue. YOLO mode bypasses these review points.

## 1. Establish the concept

Ask for the video's objective, intended viewer, product or occasion, single takeaway, and desired action. Ask where it will be posted and whether it is a Reel/Short, feed video, Story, YouTube landscape video, site hero, presentation, or ad. Clarify the intended duration, orientation and resolution, language, region, deadline, and whether one master or several platform variants are needed. Check current platform specifications when exact export rules or safe areas matter. Suggest defaults with a reason instead of making the user look up pixel dimensions.

Discuss emotional tone, references the user likes, brand colors/fonts/logo, desired use of motion graphics versus real footage, and examples to avoid. Note any offer, claim, price, date, legal text, or contact details that require verification. Summarize the brief in a few lines and propose two or three distinct video concepts; recommend one and ask which direction to develop. Do not start a full render before the direction is settled.

## 2. Brainstorm and settle the script

Write a timed sequence with hook, core message, proof or demonstration, and closing line or CTA when applicable. Offer useful alternatives for the hook and wording, not three cosmetic paraphrases. Ask how much should be spoken versus shown as captions, whether narration is needed, the language mix (Nepali, English, Hindi), preferred voice and pronunciation, and whether music or sound effects fit the brief. For Nepali, show the actual Devanagari lines. Share the complete draft with estimated seconds for each line and invite edits; revise until the user accepts a direction or delegates the remaining copy decisions.

## 3. Map visuals and assets

Provide a scene table with **time range, spoken line, on-screen text, visual source, motion or transition, and audio cue**. For every proposed photo, clip, screenshot, logo, or screen recording, specify exactly what appears, where it enters, how it moves or crops, and how long it stays. Identify which items the user will provide and which are already available or can be made as motion graphics. Ask only for the specific missing assets needed for the chosen concept; request an upload or accessible path when exact faces, products, premises, or UI accuracy matters. Show an asset checklist with preferred orientation/resolution and usage rights for external media. Use a labeled illustrative interface if the user allows a concept view of unavailable UI.

Ask whether the user wants product-only, people, place, screen capture, illustration, kinetic type, or a combination. Resolve the order of shots, where the logo appears, whether subtitles are always visible, and any platform-safe margins. Match the visual plan to the agreed script and format. Treat the approved scene table as the production brief; when the user changes a line or asset, update affected timing and scenes together.

## 4. Produce and review

Generate the voice clips, measure them, and adjust the scene table to real audio durations. Build the editable Remotion composition and render a low-resolution preview. Inspect it yourself, then show the user the preview with a compact request for feedback on hook, pacing, text, imagery, narration, and ending. Apply concrete feedback and show another preview if the revision changes the experience materially. Once the user accepts it or delegates final decisions, render and verify platform exports, then deliver the MP4 and editable source.

If the user asks for several formats, define which scenes reflow, crop, or move between formats; inspect each requested export's readable text and safe areas. If the user pauses before supplying assets or choosing the concept, retain the script, scene table, asset checklist, and any previews so the work can resume without repeating the interview.
